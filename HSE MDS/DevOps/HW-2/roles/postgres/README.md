# Роль postgres

Небольшая ансибл-роль для установки постгри на Ubuntu Server 24.04. Делал для второго дз по DevOps-2.

Идея простая: поставить постгрю, настроить её через переменные и запустить через systemd. Заодно добавил postgres-exporter, чтобы можно было собирать метрики и проверять состояние бд.

Готовую роль из Galaxy не использовал, основные задачи написал сам.

## Что делает роль

1. Ставит постгрю и нужные пакеты из стандартных репо убунты, без подключения дополнительных репо.
2. Создаёт каталоги для данных и выставляет права. Сам кластер лежит в /data/postgres/data.
3. Инициализирует кластер через pg_ctl initdb, если его ещё нет. При повторном запуске заново ничего не создаётся.
4. Настраивает postgresql.conf и pg_hba.conf через переменные. Первый передаётся словарём, второй списком словарей.
5. Запускает постгрю через свою службу postgresql-custom и включает автозапуск.
6. Проверяет подключение к бд простым запросом select 1.
7. Создаёт нужные бд и юзеров.
8. Ставит postgres-exporter, настраивает ему отдельного юзера и запускает службу через systemd.

Для конфигов сделал хендлеры, т.е. при изменении настроек постгря перезапускается или перечитывает конфиг. Если ничего не менялось, лишнего рестарта не будет.

## Переменные

Все основные настройки лежат в defaults/main.yml.

| Переменная | Что делает |
|---|---|
| postgres__version | Версия постгри, сейчас 16 |
| postgres__data_dir | Каталог данных, по умолчанию /data/postgres/data |
| postgres__config | Словарь с настройками postgresql.conf |
| postgres__hba | Список правил для pg_hba.conf |
| postgres__databases | Список бд, которые нужно создать |
| postgres__users | Список юзеров |
| postgres__exporter_version | Версия экспортера, сейчас 0.20.1 |
| postgres__exporter_user | Юзер экспортера, postgres_exporter |

Сейчас в примере создаются бд app_db и юзер app_user.

Пароль для app_user хранится в зашифрованном файле inventories/main/group_vars/all/vault.yml. В задаче создания юзеров ещё стоит no_log, чтобы пароль не светился в логах ансибла.

Пока роль делал под Ubuntu 24.04 и PostgreSQL 16, другие версии не проверял. Также каталоги /data и /data/postgres прописаны в задачах отдельно, поэтому при смене пути данных их тоже придётся поправить.

## Экспортер

Для postgres-exporter сделал отдельного системного юзера и юзера в самой постгре. Выдал ему права pg_monitor, тк для сбора метрик суперюзер не нужен.

Экспортер подключается к бд через локальный сокет, без отдельного пароля. Служба называется postgres-exporter и слушает 127.0.0.1:9187.

Сам бинарник скачивается на машину с ансиблом, потом копируется на вм. Если бинарник или конфиг службы изменятся, сработает хендлер на рестарт.

## Как запустить

Пример плейбука, который использую:

```yaml
---
- name: Configure PostgreSQL
  hosts: all
  become: true
  roles:
    - postgres
```

Перед запуском нужно установить коллекцию community.postgresql:

```bash
ansible-galaxy collection install -r requirements.yml
```

Потом из корня репо запускаю плейбук:

```bash
ansible-playbook postgres.play.yml --ask-vault-pass
```

Ансибл попросит пароль волта и выполнит задачи на vm1 из инвентаря.

## Как проверить

Сначала проверяю, что обе службы запущены:

```bash
ansible vm1 -b --ask-vault-pass -m command -a 'systemctl is-active postgresql-custom postgres-exporter'
```

В ответ должны быть две строки active.

Проверить подключение к постгре можно через:

```bash
ansible vm1 -b --ask-vault-pass --become-user postgres -m command -a 'psql -c "select 1"'
```

А метрики экспортера на самой вм:

```bash
curl -s http://127.0.0.1:9187/metrics | grep '^pg_up '
```

Если выводится pg_up 1, значит экспортер смог подключиться к постгре. Ещё можно посмотреть pg_exporter_last_scrape_error, там должно быть 0.

Отдельно проверял идемпотентность. Просто запустил плейбук второй раз без изменений и получил changed=0 в PLAY RECAP. То есть повторный прогон ничего не меняет, если всё уже настроено.
